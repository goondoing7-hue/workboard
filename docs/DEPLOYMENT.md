# 기존 온라인 업무보드에 반영하기

- 소스 저장소: https://github.com/goondoing7-hue/workboard
- 배포 브랜치: `main`
- 기존 온라인 주소: https://workboard-beta.vercel.app
- 배포 상태: https://vercel.com/lovlive-s-projects/workboard/deployments

이 작업 폴더의 `origin`과 `main`을 기존 저장소에 연결했습니다. `main`에 변경을 올리면 기존 Vercel 프로젝트가 자동으로 빌드하고 같은 주소에 배포합니다.

## 수정 완료 후 배포

```powershell
npm.cmd run publish -- "변경 내용"
```

위 명령은 저장소와 브랜치를 확인하고, 원격 변경 충돌 여부를 확인한 뒤 테스트와 빌드를 실행합니다. 모두 성공하면 지정한 소스·설정·개발 문서만 커밋하고 GitHub에 올립니다. Vercel 빌드는 그 뒤 실행되므로 배포 상태가 Ready인지 확인해야 합니다. 빌드 또는 업로드가 실패하면 중단하며, 강제로 덮어쓰지 않습니다.

사용자는 Codex에 기능 수정을 요청하면 됩니다. 이 작업에서는 수정 완료 시 검증과 온라인 반영까지 수행합니다. 입력 중인 파일을 저장할 때마다 배포하는 방식은 아니며, 완성된 변경을 기준으로 올립니다. 별도 ZIP 업로드는 필요하지 않습니다.

## 코드와 업무 데이터

`tmp`, `output`, `artifacts`, 로컬 인증 설정, `.env`, 생성된 빌드와 검증 파일은 배포 명령의 업로드 대상이 아닙니다. 내담자·상담일지 등 브라우저 저장 데이터도 GitHub에 올라가지 않습니다.

온라인 주소와 localhost는 브라우저 저장소가 다릅니다. 코드 배포만으로 데이터나 OAuth 설정을 복사하지 않습니다. 온라인에서 구글 캘린더를 쓰려면 그 주소에서 한 번 연결해야 합니다. 기존 온라인 데이터는 그대로 유지됩니다.

기존 Netlify 주소에는 이 Vercel 연결만으로 변경이 반영되지 않습니다. 이번 배포 대상은 기존 GitHub 저장소에 연결된 Vercel 주소입니다.
