# 구글 상담 캘린더 연결

상담 전용 공개 캘린더의 예약을 업무보드의 **상담·일정**에 함께 표시합니다. 직접 등록한 상담도 두 화면에서 같은 예약을 사용합니다.

## 사용법

1. 화면 맨 위 **‘이 기기만’ 옆 달력 아이콘 → 연결하기**를 누릅니다. 연결 상태·새로고침·권한 설정은 이 아이콘 안에서 확인합니다.
2. 구글 캘린더 공유 링크나 캘린더 ID를 붙여넣고 **연결하고 가져오기**를 누릅니다.
3. 가져온 예약에는 **구글** 표시가 붙습니다. 연필 버튼에서 내담자와 상담 유형을 연결할 수 있습니다. 이름만으로 사람을 추정하지 않습니다.
4. 구글 예약의 제목·날짜·시간·장소는 구글 캘린더에서 수정합니다. 업무보드에서는 내담자 연결, 상담일지, 완료 기록을 관리합니다.

앱을 열 때, 다시 돌아올 때, 앱이 보이는 동안 5분마다 확인합니다. **새로고침**으로 즉시 확인할 수도 있습니다. 구글 공개 피드 자체의 갱신 지연이 있을 수 있습니다. 앱을 닫은 동안에는 조회하지 않습니다.

조회 범위는 서울 시간 기준 전년도 1월 1일부터 다음 연도 12월 31일까지입니다. 범위 밖에 이미 저장된 기록은 유지됩니다. 원본이 삭제·취소되면 업무보드에서 취소 상태로 남기며 상담일지는 삭제하지 않습니다. 연결 중지는 자동 조회만 멈춥니다.

## 연결 방향과 보관

공개 연결은 **구글 캘린더 → 업무보드** 읽기 기능입니다. **권한 연결**에서 OAuth 클라이언트 ID를 저장하고 구글 계정으로 승인하면, 이후 업무보드에 새로 등록한 상담 예약도 선택한 구글 캘린더에 등록합니다. 기존 예약 전체를 일괄 전송하지 않습니다. 기존 Google Drive 백업 연결이나 Codex의 구글 커넥터 인증은 업무보드의 Calendar 쓰기 권한을 대신하지 않습니다.

구글에는 ‘상담 예약’이라는 제목, 날짜·시간, 선택한 장소만 공개합니다. 내담자 이름·연락처·메모·상담일지·첨부는 보내지 않습니다. 중복 방지용 무작위 로컬 예약 ID를 비공개 메타데이터에 넣습니다. 시간 미정은 종일 일정으로 등록됩니다. 전송 후에는 구글 원본의 날짜·시간·장소 변경을 가져오므로, 일정 수정·취소는 구글에서 하고 업무보드에서는 내담자 연결·상담일지·완료 상태를 관리합니다.

쓰기 권한 범위는 `calendar.events.owned`입니다. 본인이 소유한 캘린더의 일정 권한이며, 업무보드는 설정한 상담 캘린더만 호출합니다. 토큰은 메모리에만 보관하며 새로고침·잠금·만료 뒤에는 **권한 연결**이 다시 필요합니다. 권한이 없으면 새 예약은 로컬에 대기하며, 연결 후 전송합니다. 전송 실패는 자동으로 반복하지 않고 **대기 예약 다시 전송**으로 확인합니다. 재시도는 같은 이벤트 ID를 사용하며, 공개 피드가 먼저 도착해도 기존 내담자 연결과 일지를 보존합니다. 로컬 저장 성공 전에는 전송을 시작하지 않습니다.

Google Cloud의 웹 애플리케이션 OAuth 클라이언트에 현재 사이트 원본을 등록하고 Calendar API를 사용 설정해야 합니다. 로컬 개발은 `http://localhost`와 `http://localhost:3000`을 승인된 JavaScript 원본에 추가합니다. 테스트 상태인 앱은 사용하는 계정을 테스트 사용자로 등록합니다. 클라이언트 보안 비밀번호는 이 연결에 사용하지 않습니다.

공개 일정은 누구나 볼 수 있으므로 캘린더 제목에는 실명 대신 내담자 코드를 사용하고, 상담 내용은 업무보드 상담일지에 보관하는 것이 좋습니다. 연결한 ID와 가져온 예약은 기존 업무보드 데이터에 포함되어 로컬 저장·비밀번호 잠금·백업 규칙을 따릅니다. API 응답은 서비스 워커에 따로 캐시하지 않습니다.

## 실행 환경

- 로컬: `npm.cmd run dev` 또는 `npm.cmd run preview`의 `/api/google-calendar`로 읽습니다.
- Vercel: `api/google-calendar.js`, Netlify: `netlify/functions/google-calendar.js`와 `/api/google-calendar` 연결 경로를 제공합니다. 실제 배포는 이번 작업에서 수행하지 않았습니다.
- HTML 파일만 직접 열거나 API 없는 정적 호스팅에서는 구글 가져오기를 사용할 수 없습니다. 이미 저장한 업무보드 데이터는 유지됩니다.
- API 키 없이 Google의 공개 iCal 주소만 읽습니다. 비공개 캘린더는 이 방식으로 읽을 수 없습니다.

반복·종일·이동·취소·시간대 변환은 `ical.js`로 처리합니다. 잘못되었거나 지원하지 않는 반복 규칙, 크기·건수·시간 제한을 넘는 응답은 전체 요청을 오류로 처리하며 기존 데이터를 유지합니다.

## 검증

가상 공개 피드로 상담·일정 동시 표시, 반복 회기, 내담자 연결, 완료 처리, 원본 시간 변경 후 일지·연결 보존, 중복 재조회, 새로고침 유지를 확인했습니다. 실제 제공 캘린더는 읽기 연결 및 0건 응답을 확인했으며 테스트 일정을 외부 계정에 생성하지 않았습니다.

OAuth·쓰기 기능 추가 후 `npm.cmd test` 91개와 `npm.cmd run build`가 통과했습니다. 공개 연결은 모바일 390px 화면에서 가로 넘침이 없고, 실제 업무보드 새로고침 뒤 연결 설정이 유지되는 것을 확인했습니다. OAuth 단위 테스트는 가짜 GIS와 API 응답을 사용하여 권한 거부·만료·잠금·409 재시도·개인정보 제외를 검증합니다.

별도 `localhost:3002` 가상 OAuth 환경에서 권한 연결 → 새 상담 등록 → 구글 표시 → 공개 피드 재조회 → 페이지 새로고침까지 확인했습니다. 가상 API의 실제 생성은 1회였고, 내담자 연결·메모는 보존되며 외부 전송용 본문에 이름·메모가 없었습니다. 재시작하면 재연결 안내가 나타나고 브라우저 오류는 없었습니다.

2026-09-21 실제 환경에서 Calendar API를 사용 설정하고, 기존 OAuth 클라이언트의 승인된 JavaScript 원본에 `http://localhost`와 `http://localhost:3000`을 등록했습니다. Google 계정 승인 후 업무보드의 **새 상담 자동 등록 켜짐** 표시와 `events.list` 응답의 `accessRole: owner`를 확인하여 실제 쓰기 권한 연결을 완료했습니다. 실제 외부 계정에 테스트 이벤트는 생성하지 않았습니다.

참고: [Google 공개 캘린더 안내](https://support.google.com/calendar/answer/37083?hl=ko), [Calendar 권한 범위](https://developers.google.com/workspace/calendar/api/auth).
