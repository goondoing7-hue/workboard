# Google 캘린더 연결 유지

기존 브라우저 전용 연결은 앱을 닫거나 단기 토큰이 만료되면 다시 승인해야 했습니다. 서버 연결을 설정하면 Google의 authorization code 흐름으로 장기 갱신 권한을 받아, 같은 브라우저에서 앱을 다시 열 때 연결을 복구합니다. 설정되지 않은 배포는 기존 수동 연결을 유지하고 화면에 자동 유지 미설정 상태를 표시합니다.

## 서버 설정

Google Cloud 프로젝트 `kisung-workboard`의 웹 OAuth 클라이언트가 필요합니다. 승인된 JavaScript 원본은 `https://workboard-beta.vercel.app`, `http://localhost:3000`, `http://localhost`입니다. GIS 팝업 코드 방식은 토큰 교환의 redirect_uri로 페이지의 origin을 사용하며 별도 콜백 페이지를 요구하지 않습니다.

1. 클라이언트 보안 비밀번호가 들어 있는 웹 OAuth JSON을 본인이 Google Cloud에서 다운로드합니다. 비밀값을 대화나 GitHub에 붙여 넣지 않습니다. 기존 보안 비밀번호는 Google에서 재열람할 수 없으므로 보관한 JSON이 없으면 새 비밀번호를 추가해야 합니다. 기존 값을 삭제하거나 비활성화하지 않습니다.
2. `node scripts/configure-calendar.js "다운로드한 JSON의 절대 경로"`를 실행합니다. 서버만 읽는 `.env.local`이 생성되며 기존 세션 암호화 키는 유지합니다.
3. `.env.example`의 다섯 환경변수를 기존 Vercel `lovlive-s-projects/workboard` 프로젝트의 **Production** 환경에 설정합니다. 비밀번호와 세션 키는 Sensitive로 저장합니다. Preview에는 배포하지 않습니다.
4. 서버 환경변수 반영 후 프로덕션을 재배포하고 로컬 서버를 다시 시작합니다.
5. Google OAuth 앱의 게시 상태가 **Testing**이면 Calendar 갱신 토큰은 7일 뒤 만료됩니다. 브랜딩 필수 정보를 완료하고 **Production**으로 전환한 뒤 새 권한을 승인해야 합니다. 앱 공개 범위·경고·동의는 계정 소유자가 확인합니다.
6. 업무보드의 캘린더 아이콘 → 권한 연결에서 한 번 승인합니다. localhost와 온라인은 서로 다른 사이트이므로 각각 한 번 연결합니다.

## 동작과 한계

- 갱신 토큰은 서버 키로 AES-256-GCM 암호화한 HttpOnly/SameSite 쿠키에만 보관합니다. HTTPS에서는 Secure/`__Host-` 쿠키를 사용합니다. 브라우저 스크립트·업무 데이터·Google Drive 백업·GitHub에는 토큰이나 클라이언트 비밀번호를 넣지 않습니다.
- 서버 재시작이나 새 배포로 메모리 토큰이 없어져도 암호화 쿠키로 갱신합니다. 암호화 키가 바뀌면 기존 연결을 복구할 수 없습니다.
- 쿠키 유효기간은 승인부터 180일입니다. 사이트 데이터 삭제, Google 권한 철회·만료, 계정 보안 정책 변경 때에는 다시 승인해야 합니다. 무기한 권한을 보장하지 않습니다.
- 앱을 잠그면 진행 중인 요청과 화면의 인증 상태를 중단합니다. 잠금을 해제하면 저장된 연결을 복구합니다. 자동 등록 끄기는 이 브라우저 연결을 삭제하며 기존 Google 일정은 지우지 않습니다. 같은 OAuth 클라이언트의 Drive 권한에 영향을 주지 않도록 Google 전체 동의는 자동 철회하지 않습니다.
- 새 예약을 로컬에 성공적으로 저장한 뒤 Google로 전송합니다. 전송 중 앱이 닫혀도 같은 예약 ID로 다시 확인하여 중복 생성을 막습니다. 일시적인 네트워크 장애는 대기 후 재시도하며 권한 팝업을 자동으로 열지 않습니다.
- Google로 보내는 내용은 ‘상담 예약’ 제목과 날짜·시간·지정된 장소, 내부 중복 방지용 식별자뿐입니다. 실명·연락처·상담일지·첨부는 전송하지 않습니다.
- 앱을 열어 둔 동안 Google의 공개 캘린더 변경을 정기 확인합니다. 앱이 닫혀 있던 동안의 변경은 다시 열 때 가져옵니다. 로컬 브라우저에만 있는 업무 데이터의 무인 백그라운드 동기화를 의미하지 않습니다.

## 검증

`npm test`는 실제 계정 없이 코드 교환, 서버 재시작 후 복원, 액세스 만료 갱신, CSRF·원본 제한, 잘못된 쿠키, 권한 철회, 개인정보 전송 제한, 잠금·응답 경쟁 상태를 확인합니다. 실제 설정 완료 후에는 한 번 승인하고 창을 닫았다가 다시 열어 자동 연결 복원을 확인해야 합니다.

공식 문서: [Google 코드 모델](https://developers.google.com/identity/oauth2/web/guides/use-code-model), [갱신 토큰 만료](https://developers.google.com/identity/protocols/oauth2#expiration).
