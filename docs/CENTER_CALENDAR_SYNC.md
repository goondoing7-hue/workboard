# 센터 일정과 상담 분리

일정 화면의 `상담`은 `resv`, `센터 일정`은 사업에 속하지 않는 `events`를 표시한다. 상담 표시 여부는 `__counsel__`로 별도 저장한다. 기존 센터 필터를 꺼 두었어도 상담은 독립적으로 표시된다.

센터 캘린더는 서버의 `GOOGLE_CENTER_CALENDAR_ID`와 연결한다. 로컬 `.env.local` 및 Vercel Production 환경변수에 같은 ID를 지정한다. 기존 Google OAuth의 `calendar.events.owned` 권한과 HttpOnly 세션을 함께 사용한다. 센터 목록·개별 조회·추가·수정·삭제는 고정 캘린더의 소유 권한을 확인한 서버에서만 수행한다.

앱이 열려 있고 화면이 활성화된 동안 약 45초마다 Google 변경을 가져온다. 다시 열거나 온라인으로 돌아오면 재확인한다. 닫힌 브라우저의 로컬 데이터를 백그라운드에서 수정하는 방식은 아니다.

새 센터 일정 및 일정 필드 수정은 먼저 브라우저에 저장한 뒤 Google로 전송한다. 제목·날짜·시간·장소·설명만 연동하며 업무 내부 필드와 완료 체크는 로컬에 보존한다. 기존 로컬 일정은 최초 연결만으로 전송하지 않는다. 완료 표시만 바꾸어도 전송하지 않는다. 사업 일정과 보수교육은 대상이 아니다.

`centerSync`에 결정적 원격 ID, ETag, 수정 버전, 대기 상태를 보관한다. 재시도는 같은 ID를 사용한다. 다른 기기나 Google에서 동시에 수정하면 자동 덮어쓰기 대신 사용자에게 보존할 변경을 선택하게 한다. 삭제도 큐에 남겨 성공 확인 후 제거한다. 전체 목록을 성공적으로 가져온 경우에만 원격에서 사라진 일정을 숨기며 대기 중인 로컬 변경은 보존한다.

종일 일정은 Google의 exclusive 종료 날짜를 보관한다. 화면에서는 사용자가 마지막 날을 선택한다. 여러 날의 시간 일정은 잘린 표시값 대신 원본으로 편집한다. 반복 일정은 선택한 회차만 수정한다.

연결을 중지하면 저장된 일정은 남는다. 상담 패널에서 Google 계정 권한 자체를 해제하면 공유 세션을 사용하는 센터 연결에도 재승인이 필요하다.

검증은 도메인 큐/재시도/충돌/종일·반복 처리, 서버의 범위·권한·페이지네이션·ETag, 별도 포트의 가짜 Google 서버를 통한 UI 흐름으로 수행한다. 실제 사용자 캘린더에는 테스트 일정을 만들지 않는다.

상담 캘린더는 공개 피드가 403/404이면 같은 서버 세션을 사용한 읽기 전용 인증 조회로 전환한다. 공개 설정을 바꾸지 않아도 되며, 기존 iCalUID와 원래 반복 회차를 보존해 내담자 연결·일지를 유지한다. 새 브라우저에서는 공통 Google 권한을 먼저 연결한다.
