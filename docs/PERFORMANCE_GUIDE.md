# 상담 실적 관리

주소: https://workboard-beta.vercel.app/performance.html

업무보드의 상담 화면에서 **상담 실적 관리**를 열어도 된다. 기존 업무보드 데이터와 별도 저장소를 사용하며, 해당 화면을 여는 것만으로 기존 상담정보나 캘린더를 가져오지 않는다.

## 입력과 집계

- 실제 활동을 날짜별로 기록한다. 마음결 개인상담도 개인상담으로 입력한다.
- 횟수, 참여 인원 누계, 실제 총 진행 분을 직접 입력한다. 한 사람과 4회 상담했다면 4회·연인원 4명이며, 같은 사례코드로 실인원 중복을 제거한다.
- 집단의 시간에는 인원을 곱하지 않는다. 참여자 코드는 같은 사람에게 일관되게 사용한다. 코드가 없거나 불완전한 기록의 실인원을 임의 추정하지 않는다.
- 예정·취소, 가져온 후 아직 확인하지 않은 기록, 충돌 검토 중인 기록은 완료 실적에서 제외한다.
- 센터와 수퍼바이저의 확인 상태를 각각 기록한다. 센터 확인은 한상·병영생활전문상담관, 수퍼바이저 확인은 한상심에 적용한다. 각 인정 대상 체크로 집계 포함 여부를 조정한다.
- 확인 완료에는 확인자와 확인일을 적는다. 실제 내용·수량·기관 등 핵심 항목을 변경하면 이전 인정은 재확인 상태로 전환된다. 이전 내용과 인정 기록은 변경 이력 백업에 남는다.
- 합계에서 인원은 코드로 확인되는 중복제외 인원이다. 참여 누계와 코드 미확인 기록을 함께 검토한다. 슈퍼비전·집단·검사 등 서로 다른 활동의 전체 횟수는 활동 건수로 해석하고 개인상담 회기와 혼동하지 않는다.

## 기존 업무보드 기록 가져오기

백업 화면의 완료 상담 가져오기는 사용자가 버튼을 눌렀을 때만 현재 주소의 `workboard:data`를 읽는다. 완료 예약만 가져오며, 상담일지 본문·내담자 실명·연락처는 복사하지 않는다. 사례코드와 예약 ID를 연결해 같은 기록을 반복 가져오지 않는다. 실제 활동 종류와 시간을 검토하고 저장하기 전까지는 합계에 포함하지 않는다. 구글 캘린더 갱신이 실적 기록을 다시 변경하지 않는다.

## 저장과 복구

저장 버튼을 누르면 기기 저장소에 즉시 기록하고 추가 기기 백업(IndexedDB)에도 보존한다. 같은 기기의 두 저장소는 기기 분실에 대비한 외부 백업을 대신하지 않는다. Google 연결 후에는 앱이 열려 있고 온라인일 때 변경을 약 1.2초 후 자동 전송하며, 대기 기록·실패 사유·마지막 확인 시각을 표시한다. 오프라인 기록은 다음 접속 때 다시 전송한다.

Google Sheets에는 사람이 읽을 수 있는 활동 항목과 완전복구 JSON을 변경 이력 형태로 추가한다. 수정·삭제도 이력으로 저장하므로 시트의 행 합계를 현재 실적으로 사용하지 않는다. 현재 실적 합계는 프로그램에서 확인한다. 시트 행을 직접 편집하지 말고 프로그램에서 수정한다. JSON 전체 백업과 필터 결과 CSV를 별도로 다운로드할 수 있다.

복구 파일은 기존 기록과 ID로 병합한다. 같은 기록의 서로 다른 수정이 발견되면 양쪽 버전을 보존하고 선택하도록 한다. 잘못된 파일·실패한 조회를 빈 데이터로 처리하지 않는다. 기기 기록이 손상되었을 때 백업 파일을 가져오면 손상 원본은 별도로 보존한 후 복구한다.

인증 설정과 제한은 [PERFORMANCE_BACKUP.md](PERFORMANCE_BACKUP.md), 병영 실적 기준과 자료 범위는 [PERFORMANCE_MILITARY_SOURCE.md](PERFORMANCE_MILITARY_SOURCE.md)를 참고한다.
