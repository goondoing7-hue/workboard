# 상담 실적 관리

주소: https://workboard-beta.vercel.app/performance.html

업무보드의 상담 화면에서 **상담 실적 관리**를 열어도 된다. 기존 업무보드 데이터와 별도 저장소를 사용하며, 해당 화면을 여는 것만으로 기존 상담정보나 캘린더를 가져오지 않는다.

## 입력과 집계

- 실제 활동을 날짜별로 기록한다. 마음결 개인상담도 개인상담으로 입력한다.
- 횟수, 참여 인원 누계, 실제 총 진행 분을 직접 입력한다. 한 사람과 4회 상담했다면 4회·연인원 4명이며, 같은 사례코드로 실인원 중복을 제거한다.
- 집단의 시간에는 인원을 곱하지 않는다. 참여자 코드는 같은 사람에게 일관되게 사용한다. 코드가 없거나 불완전한 기록의 실인원을 임의 추정하지 않는다.
- 예정·취소, 가져온 후 아직 확인하지 않은 기록, 충돌 검토 중인 기록은 완료 실적에서 제외한다.
- 활동 자체의 센터 확인과 수퍼바이저 확인을 각각 기록한다. 센터 확인은 한국상담학회·병영생활전문상담관, 수퍼바이저 확인은 한국상담심리학회에 적용한다. 학회 수련 항목별 승인 내역은 아래 인정 현황에서 별도로 관리한다.
- 확인 완료에는 확인자와 확인일을 적는다. 실제 내용·수량·기관 등 핵심 항목을 변경하면 이전 인정은 재확인 상태로 전환된다. 이전 내용과 인정 기록은 변경 이력 백업에 남는다.
- 합계에서 인원은 코드로 확인되는 중복제외 인원이다. 참여 누계와 코드 미확인 기록을 함께 검토한다. 슈퍼비전·집단·검사 등 서로 다른 활동의 전체 횟수는 활동 건수로 해석하고 개인상담 회기와 혼동하지 않는다.

## 기존 업무보드 기록 가져오기

백업 화면의 완료 상담 가져오기는 사용자가 버튼을 눌렀을 때만 현재 주소의 `workboard:data`를 읽는다. 완료 예약만 가져오며, 상담일지 본문·내담자 실명·연락처는 복사하지 않는다. 사례코드와 예약 ID를 연결해 같은 기록을 반복 가져오지 않는다. 실제 활동 종류와 시간을 검토하고 저장하기 전까지는 합계에 포함하지 않는다. 구글 캘린더 갱신이 실적 기록을 다시 변경하지 않는다.

## 학회별 승인 현황과 수퍼바이저

인정 현황에서 한국상담심리학회 상담심리사 2급, 한국상담학회 1급 B범주의 수련 항목을 선택한다. 제공한 캡처를 기준으로 30개 항목을 구성했으며, 사례·회기·시간·집단·제출서류의 단위를 각각 유지한다. 한국상담학회의 720시간, 별도 연수 80시간, 제출서류를 서로 더하지 않는다. 항목을 펼치면 활동 제목, 사례코드, 등록량, 승인 상태, 수퍼바이저, 확인자, 확인일, 증빙을 확인한다.

승인내역은 활동 기록을 연결하거나 직접 등록할 수 있다. 기본 상태는 미요청이며 승인 대기·승인 완료·보완/반려로 관리한다. 승인 완료에는 확인자·확인일과 세부조건 확인이 필요하다. 수량이 기준에 도달했다는 이유만으로 승인 처리하지 않는다. 입력한 승인량을 합산하므로 같은 사례나 자료의 중복 범위를 확인해야 한다. 기존 활동의 일괄 확인은 보존하지만 특정 수련 항목으로 추정하여 자동 승인하지 않는다. 연결 활동이 수정·삭제되면 해당 승인량은 재확인 전까지 제외한다.

수퍼바이저 관리에서 이름·소속·자격/등록번호·적용 학회를 등록한다. 활동 기록, 항목별 승인내역, 수련 일정에서 선택할 수 있다. 비활성화하면 신규 선택 목록에서 숨겨지며, 이름을 수정해도 이전 승인내역에 저장한 이름은 바뀌지 않는다. 근거와 캡처가 잘린 범위는 [PERFORMANCE_APPROVAL_SOURCE.md](PERFORMANCE_APPROVAL_SOURCE.md)를 참고한다.

## 수련 캘린더와 실적 전환

수련 캘린더의 **Google 연결 · 전용 캘린더 만들기**에서 본인 계정으로 승인하면 `상담·수련 실적` 비공개 보조 달력을 만든다. 이미 이 앱에서 만든 달력은 재사용한다. 실적 앱에 등록한 일정을 Google에 전송하고, Google에서 전용 달력을 선택해 추가·수정한 일정도 앱에 가져온다. 앱이 열려 있고 온라인일 때 저장 후 약 1.2초에 전송하며, 60초마다 및 화면 복귀 때 다시 확인한다. **지금 동기화**로 즉시 확인할 수도 있다. Google 직접 입력 일정은 학회와 수련 항목을 먼저 분류한다.

Google 계정의 최초 연결 승인을 마쳐야 실제 달력 생성과 동기화가 시작된다. 계정 선택·승인 창이 보이지 않으면 Chrome이나 Edge에서 실적 관리 주소를 열고 다시 연결한다. 연결 화면에 달력 이름과 동기화 상태가 표시되는지 확인한다. Google Sheets 백업은 **백업 · 연결**에서 별도로 연결한다.

달력의 예정 일정을 실적으로 자동 계산하지 않는다. 진행을 마친 뒤 **실적 등록**에서 실제 진행 시간·횟수·인원과 항목별 등록 수량을 확인하면 활동 실적과 미요청 승인내역을 함께 만든다. 같은 일정에서 반복 실행해도 중복 생성하지 않는다. 이후 일정 시간 변경이나 Google 삭제가 이미 완료한 활동·승인을 삭제하거나 다시 계산하지 않는다.

양쪽에서 같은 일정을 바꾸면 양쪽 내용을 비교하고 사용할 버전을 선택한다. 취소는 Google 일정에도 반영되며 오류나 연결 중단 동안 전송 대기를 보존한다. 반복 일정은 선택한 회차만 다룬다. 상담 내용이나 로컬 메모, 수퍼바이저 이름은 Google 일정에 전송하지 않는다. 연결 설정과 한계는 [PERFORMANCE_CALENDAR.md](PERFORMANCE_CALENDAR.md)를 참고한다.

## 저장과 복구

저장 버튼을 누르면 기기 저장소에 즉시 기록하고 추가 기기 백업(IndexedDB)에도 보존한다. 같은 기기의 두 저장소는 기기 분실에 대비한 외부 백업을 대신하지 않는다. Google 연결 후에는 앱이 열려 있고 온라인일 때 변경을 약 1.2초 후 자동 전송하며, 대기 기록·실패 사유·마지막 확인 시각을 표시한다. 오프라인 기록은 다음 접속 때 다시 전송한다.

Google Sheets에는 사람이 읽을 수 있는 활동 항목과 완전복구 JSON을 변경 이력 형태로 추가한다. 수정·삭제도 이력으로 저장하므로 시트의 행 합계를 현재 실적으로 사용하지 않는다. 현재 실적 합계는 프로그램에서 확인한다. 시트 행을 직접 편집하지 말고 프로그램에서 수정한다. JSON 전체 백업과 필터 결과 CSV를 별도로 다운로드할 수 있다.

복구 파일은 기존 기록과 ID로 병합한다. 같은 기록의 서로 다른 수정이 발견되면 양쪽 버전을 보존하고 선택하도록 한다. 잘못된 파일·실패한 조회를 빈 데이터로 처리하지 않는다. 기기 기록이 손상되었을 때 백업 파일을 가져오면 손상 원본은 별도로 보존한 후 복구한다.

인증 설정과 제한은 [PERFORMANCE_BACKUP.md](PERFORMANCE_BACKUP.md), 병영 실적 기준과 자료 범위는 [PERFORMANCE_MILITARY_SOURCE.md](PERFORMANCE_MILITARY_SOURCE.md)를 참고한다.
